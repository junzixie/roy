### 主要问题

1. **超大组件**
   - LeftSidebar.tsx: 5267 行
   - AgentView.tsx: 3516 行
   - SidePanel.tsx: 2553 行

## 💡 解决方案

### 方案 A：快速优化（立即见效）

#### 1. 启用性能调试
在浏览器控制台运行：
```javascript
localStorage.setItem('roy-performance-debug', '1')
```
然后重启 Roy，访问 `?perf=1` 查看性能指标

#### 2. 关闭不必要的功能
编辑 `~/.roy/settings.json`:
```json
{
  "wallpaper": {
    "dynamic": "none",
    "sceneFps": 0
  },
  "visionRelay": {
    "enabled": false
  }
}
```

#### 3. 减少动画
```json
{
  "enableAnimations": false
}
```

### 方案 B：代码优化（需要重新构建）

#### 1. 优化 AgentView（3516 行 → 拆分）

**问题代码**：
```typescript
function AgentView() {
  // 每次都重新计算
  const messages = useAgentMessages(sessionId)
  
  // 没有 memo，每次父组件更新都重新渲染
  return (
    <div>
      {messages.map(msg => <Message key={msg.id} {...msg} />)}
    </div>
  )
}
```

**优化后**：
```typescript
const Message = React.memo(({ content, role }) => {
  return <div>{content}</div>
}, (prev, next) => {
  // 只在内容真正变化时才重新渲染
  return prev.content === next.content && prev.role === next.role
})

function AgentView() {
  const messages = useAgentMessages(sessionId)
  const debouncedMessages = useDebounce(messages, 100)
  
  return (
    <VirtualList
      items={debouncedMessages}
      itemHeight={80}
      containerHeight={600}
    />
  )
}
```

#### 2. 虚拟化长列表

**会话列表**（LeftSidebar）：
```typescript
import { Virtuoso } from 'react-virtuoso'

<Virtuoso
  data={sessions}
  itemContent={(index, session) => (
    <SessionCard key={session.id} session={session} />
  )}
  style={{ height: '100%' }}
/>
```

**消息列表**（AgentMessages）：
```typescript
<Virtuoso
  data={messages}
  followOutput="smooth"
  itemContent={(index, message) => (
    <MessageItem key={message.id} message={message} />
  )}
/>
```

#### 3. 清理定时器

在所有使用 `setInterval` 的地方：
```typescript
useEffect(() => {
  const timers: NodeJS.Timeout[] = []
  
  timers.push(setInterval(() => {
    // 你的逻辑
  }, 1000))
  
  return () => {
    timers.forEach(clearInterval)
  }
}, [])
```

#### 4. 减少重渲染

使用 `useMemo` 和 `useCallback`:
```typescript
const expensiveValue = useMemo(() => {
  return complexCalculation(data)
}, [data])

const handleClick = useCallback(() => {
  // 处理点击
}, [dependency])
```

## 💾 检查定时器泄漏

旧版本这里给的是一条 `grep` 单行命令，但它**实际不成立**：

```bash
# 不要用这条：它按 -A5 上下文过滤，同一个文件里
# 别处的 clearTimeout 会把真正泄漏的那处一起"洗白"，
# 而紧邻的无关 clearTimeout 也会让泄漏点漏报。
grep -rn "setInterval\|setTimeout" ... -A5 | grep -v "clearInterval\|clearTimeout"
```

可靠的判断标准只有一条：**每次 `setTimeout`/`setInterval` 都必须有对应的清理**，
且清理要在 `useEffect` 的返回函数里。按这个规则人工过一遍
`apps/electron/src/renderer` 下的 `useEffect`，比任何 grep 都准。

真要自动化，用 ESLint 的 `react-hooks/exhaustive-deps` 配合自定义规则，
而不是正则匹配。

## 🎯 建议执行顺序

1. **先确定瓶颈在哪**（不要跳过）
   用 React DevTools Profiler 录一段真实卡顿操作，看清是哪个组件在反复 commit。
   凭感觉改组件通常白改。

2. **按瓶颈改单个文件**
   只改 Profiler 指出的那个，改完再录一次对比。

3. **不要做的事**
   - 跑 `scripts/apply-performance-optimization.js`：它只清理 `settings.json`
     里从未生效的历史字段，对渲染性能零影响
   - `npm install react-virtuoso`：该依赖已移除（零引用），装了也不会有任何变化
   - 「关闭动态壁纸」：那是观感取舍，不是性能修复；壁纸已经做了双缓冲与内容门控

4. **下个版本**（深度重构）
   - 拆分超大组件
   - 重构状态管理
   - 添加性能监控面板
