# 上下文压缩策略（近满再压）

更新：2026-10-29

## 默认策略
- **默认阈值：90%（保留缓存 / cache-preserving）**，对齐 Claude / Codex 近满再压，避免没聊几句就摘要。
- 角标可选：保留缓存 · 90% / 均衡 · 80% / 积极回收 · 70%。
- Sol（372K 已验证窗口）期望阈值：
  - **90% ≈ 334,800 tokens**
  - **80% ≈ 297,600 tokens**
- 未验证窗口仍受 28 万硬顶约束：90% → **252,000**；80% → **224,000**。

## 工具输出预截断（Feibo）
- 单条工具输出超过 **12,000 字符**时保留头 8k + 尾 3k，中间标省略。
- 接线：fterToolCall（写入时裁）+ 	ransformContext（请求/压缩前再裁历史大 toolResult）。

## 空闲静默预压缩
- **水位：有效窗口约 65%**（低于正式 90% 线）。
- **空闲：默认 45 秒**无流式回复；已达正式线则约 1.5 秒后尽快整理。
- 触发后走与手动/自动相同的 `session.compact()` 摘要逻辑；UI 仅角标轻转（reason=`idle`），不大条「正在整理上下文」。
- 用户发消息会取消预约；若压缩已在跑则中止并让路给正常请求。
- 相关：`idle-precompaction-scheduler.ts`、`agent-orchestrator` / `agent-service` 接线。
