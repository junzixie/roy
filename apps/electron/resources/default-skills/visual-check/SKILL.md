# 视觉自检

做完看得见的东西（网页、HTML 报告、工作台界面、海报、PPT 页面、视频帧），交付前自己先看一眼，回答里给出截图路径，不要只说「应该没问题」。

## 用哪个工具截图

- **本地 HTML 文件 / 项目页面**：`BrowserPreviewOpen` 打开（传 HTML 文件或含 index.html 的目录），再 `BrowserScreenshot` 截图。
- **本地开发服务或线上网页**（如 http://localhost:5173）：`BrowserNavigate` 打开，再 `BrowserScreenshot`。
  - 要看手机效果时，先说明当前截图是桌面宽度；需要时让页面支持窄屏后再截一次对比。
  - 页面有深色 / 浅色两套主题的，两套各截一张。
- **桌面软件窗口**（Roy 外的程序、Electron 应用、游戏启动器等）：`screen_capture`，`window` 填窗口标题的一部分。
- 截图工具大多支持 `question`：告诉看图模型重点看什么，比如「标题有没有被截断」「按钮是否对齐」。

## 流程

1. **改之前先截一张**作为对照（改动较大时）。
2. 改完再截，同样的页面、同样的尺寸。
3. 按下面的检查清单逐条看，必要时用 `question` 让看图模型帮忙核对。
4. 回复里写：改了什么、截图路径（改前 / 改后）、清单里发现的问题；有问题先修，修完再截图确认。

## 检查清单

- **文字**：没有溢出、截断、重叠，没有乱码或方块字。
- **布局**：元素对齐、间距一致，没有大片意外空白，窄屏下不横向滚动。
- **深浅色**：两种主题下文字都看得清，没有白底白字、黑底黑字。
- **状态**：空状态、加载中、出错时的样子也看一眼（能触发的话）。
- **媒体**：图片、图标、视频封面都加载出来了，没有被拉伸变形。

## 注意

- 看图模型的描述也可能看错。它说有问题、但你从代码看不出原因时，把截图路径给用户，请用户自己看一眼。
- 当前模型看不了图、设置里也没配视觉助手时，工具只会返回截图路径：如实告诉用户「已截图，路径是……，我这边看不到图片内容」，并提示去 设置 → 模型配置 → 视觉助手 选一个能看图的模型。
- 只截和任务有关的页面或窗口，不截与任务无关的隐私内容。
